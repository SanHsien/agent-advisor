# 成本與驗收紀律

目的：減少重複工作與不必要的模型呼叫；不降低正確性、風險路由或獨立審查要求。

## 選擇合作方式

- `solo` 仍是預設；不固定呼叫顧問、不固定派工、不固定模型二審。
- `delegate` 適用於規格完整、驗收明確、工作量足以抵銷說明及整合成本的工作。
- 寫出「輔助角色取代主代理的哪部分工作」。不能回答，就由主代理完成。
- 不因模型單價低就派工；比較完整任務的探索、實作、驗證、失敗、重試與整合成本。
- 一個輔助角色仍是預設上限；本次更新不授權平行擴張、不新增第五條路由。
- 顧問建議不等於 fresh reviewer 的獨立最終審查。原生顧問功能保持選用；要使用必須先確認該 runtime、provider、模型配對與費用來源支援，遵守該版路由及角色合約。

## 派工內容

保留 OBJECTIVE、FILES AND OWNERSHIP、INTERFACES、CONSTRAINTS、VERIFICATION、RETURN。
只附必要檔案位置、介面、已確定結論與短錯誤片段。不要複製整段對話、全部 logs、秘密或多個代理已查過的相同內容。
要求逐步寫入完成的檔案，回報 diff 範圍、驗證紀錄位置、未完成部分。主代理不重做已派出的實作。
穩定政策留在 skill reference；不要把大型動態用量紀錄加入常駐提示，不在同一對話反覆切換模型或重建工具集。

## 沿用可核對的驗證證據

主代理仍須讀完整 diff 並確認 ownership、介面與驗收。只在以下全部成立時沿用 worker 的同一次檢查：

1. 有真實命令、exit code、時間與保存的輸出。
2. 證據綁定完整工作樹狀態：HEAD、已修改檔案及 untracked 輸入的 hash；只綁 HEAD 不足以涵蓋未提交改動。
3. 命令、輸入、依賴、設定、環境與驗收要求一致；涉及外部狀態的證據另符合 runbook freshness。
4. 檢查後沒有影響該結果的改動；主代理實際查核以上證據，不能只相信「測試通過」。

不符合就跑最小必要檢查。新的修改使受影響證據失效；先聚焦修正與驗證，再執行 repo 明訂的交付 gate。
repo 強制由父代理重跑、獨立 checker 或完整 gate 時仍照做。達標即停；新改動、失敗或未解疑點才擴大或重跑。
未知、timeout、缺失用量均不是成功，也不是零。

## 成本證據

可用時記錄 task_id、repo、起始及交付狀態、route、role、實際 model/effort/provider、輸入／輸出／快取 token、耗時、諮詢及重試次數、驗收結果、證據位置。
保留 provider 原始欄位與來源；不同平台先確認用量語意，避免快取或父子用量重複加總。
缺欄位標 unknown；不得為取得用量啟動第二次模型呼叫。若換算美元，標明價格日期、費率來源與 estimated；訂閱額度不是 API 帳單。
每件合格交付成本 = 全部嘗試成本 / 合格交付件數；失敗、顧問、審查與重做都計入。資料不足不能宣稱省下固定比例。
這是工作合約與證據格式，不是自動用量擷取器或 runtime 硬性預算。既有 loop budget、429 有界重試、安全 hooks 與核准要求仍有效。
